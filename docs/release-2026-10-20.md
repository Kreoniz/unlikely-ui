# First alpha release

Published and verified on 2026-10-20. This document records the preparation,
public npm artifact, and first-publication tag exception.

## Release

- Package: unscoped `unlikely-ui@0.1.0-alpha.1`.
- License: MIT for package code and documentation; development artwork/fonts
  are excluded. Author credit uses the owner's public handle, Kreoniz.
- Registry: `https://registry.npmjs.org/`; access: public; tag: `next`.
- React and React DOM peers remain `^19.3.1`; fixtures use 19.3.1.
- ESM only; all twenty-one catalogue entries remain previews.
- Package repository/homepage metadata remains unset. A private source backup,
  [Kreoniz/unlikely-ui](https://github.com/Kreoniz/unlikely-ui), was subsequently
  created on 2026-10-20; it does not change the prepared npm payload.

## Completed

- Added LICENSE, release notes, package metadata, public prerelease defaults,
  a clean `prepack` build, and a full `prepublishOnly` gate.
- Updated contributor/consumer guidance and added `docs/releasing.md`.
- The workspace version badge reads the package manifest.
- Consumer checks now enforce release identity/license, export targets,
  prerelease publication defaults, license inclusion, consumer document links,
  and the package file allowlist.
- Frozen offline dependency installation passed without dependency changes.
- Formatting passed for the changed release files.
- `pnpm release:check` passed: TypeScript, six typed API tests, all 98 token
  contrast pairs, production showcase build, 35 gallery browser tests, and
  five packed browser tests in each of plain React and consumer Tailwind.
- After final publication-neutral wording changes to the shipped docs,
  `pnpm test:consumer` passed again against the final tarball, including
  declaration checks, DOM-free SSR, hydration, CSS isolation, portal themes,
  and the ten browser tests across the two consumer modes.
- npm's final publish dry run succeeded with public access and `next`, without
  running lifecycle checks again or uploading anything.
- Registry authentication verified as `kreoniz` after login refresh. Account
  2FA verified enabled with `auth-and-writes`, following the owner's setup.
- Name lookup returned E404 for `unlikely-ui`; this does not reserve it or
  guarantee registry acceptance at publication time.

The showcase and consumer fixture builds reported Vite's large-chunk advisory.
The fixture imports the entire component set and the workspace includes typed
API data and syntax highlighting. This does not describe every app's bundle;
no blanket tree-shaking or performance claim is made.

## Publication

The owner explicitly authorized publication. The ordinary command
`mise exec -- npm publish --access public --tag next --registry=https://registry.npmjs.org/`
ran the complete `prepublishOnly` gate and a clean `prepack` build, then completed
npm browser authentication. All 35 gallery browser tests, 10 packed-consumer
browser tests, 6 API tests, TypeScript checks, and 98 contrast pairs passed.

npm initially accepted the upload with HTTP 202 and exposed a temporary
`0.0.0-stage` placeholder. The real alpha became available at
`2026-10-20T15:53:42.943Z`. The public
[package version](https://www.npmjs.com/package/unlikely-ui/v/0.1.0-alpha.1)
reports MIT licensing and source commit
`c597bf688afc4d8c72abc6ab09acc98afa4fc1f5`, tagged `v0.1.0-alpha.1` in Git.

The public tarball was downloaded from npm and checked against registry
SHA-512/SHA-1 metadata. All 84 allowed files were present; runtime modules,
types, CSS, and shipped documents matched the tested output. No artwork, fonts,
local archives, or development files were included. The downloaded artifact is
55,331 bytes compressed and 226,389 bytes unpacked; its integrity is the same
as the npm dry run above. SHA-1: `9b49a2d6452ca9bd5c5c34a2a455a305158b0782`.
Local verification data is in `.local/publication-summary.json` and
`.local/registry-package/`, excluded from Git/npm.

Despite the explicit `next` publication flag, npm also assigned `latest` on
this first package publication. Removing `latest` with the ordinary CLI and
a second browser/2FA approval was rejected by npm with HTTP 400. Both `next`
and `latest` therefore point to `0.1.0-alpha.1`. This matches the upstream
[first-publish report](https://github.com/npm/cli/issues/8490); it is not an
intentional promotion to a stable release. Continue to pin the alpha's exact
version in apps and use `--tag next` for later alphas.
